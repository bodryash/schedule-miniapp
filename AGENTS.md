# AGENTS.md — как вести «:Расписание»

Памятка для ИИ-помощника (Codex, Claude и др.), который продолжает работу.
Отвечать владельцу по-русски, коротко.

## Что это

«:Расписание» — расписание вузов в Telegram и в браузере.

| Что | Где |
| --- | --- |
| Бот | [@FGPshedulebot](https://t.me/FGPshedulebot) |
| Приложение (боевое) | https://app.bodryash.ru — папка `docs/` ветки `main` |
| Бета | https://beta.bodryash.ru — ветка `beta` |
| Сайт для браузера и ПК | https://bodryash.ru |
| Свой сервер (бот, API) | https://api.bodryash.ru — `server/index.mjs` + `worker/src/*.js` |

Сервер **сам подтягивает `main` раз в минуту**: после слияния в `main` всё
выкатывается без ручного деплоя.

## Порядок работы (обязательно)

1. **Данные и сервер** (`docs/data/**`, `server/`, `worker/`, `tools/`):
   ветка от свежего `origin/main` → PR в `main` → squash-слияние → затем
   `main` вливается в `beta` (`git checkout beta && git merge origin/main && git push`).
2. **Только приложение** (`docs/app.js`, `docs/*.css`, `docs/index.html`):
   сначала **только в `beta`**. В `main` — лишь когда владелец скажет «грузи».
3. После любых изменений данных расписания:
   ```bash
   python3 tools/landing_pages.py
   python3 tools/teachers_index.py
   ```
4. Людям от имени бота **без команды владельца писать нельзя** — кроме
   благодарности за подключение (`/admin/connected`, ниже).
5. Ключи, токены, секреты — никогда не в чат, не в репозиторий.

## Данные

- Список вузов/факультетов: `docs/data/tenants.json`
  (`{id, university, faculty, path, features:[], short, tz?, source?}`).
- Факультет: `docs/data/<id>/schedule.json` и `groups.json`.
- Два формата расписания:
  - **по неделям**: `lesson.week` = `all` / `odd` / `even`, `meta` без `dated`;
  - **по датам**: `meta.dated: true`, у каждой пары `dates: ["2026-11-16", …]`.
- Пара: `{group, day(1=Пн), slot, start, end, subject, type, teacher, room,
  dates?, subgroup, elective, week, note, link}`.
- `weeks: [{from, to, parity}]`, `bells: [{n, start, end}]`.
- В приложении группа не основного вуза — это `tenant/группа` (например `msal-spo/(ПД-О)3`).

Если прислали только одну неделю, по умолчанию она повторяется каждую неделю до конца семестра.
Если на скринах конкретные даты, а недели различаются, — ставить эти даты точно.

## Закрытые адреса сервера (нужен ключ)

Ключ чтения создаёт команда **`/readkey`** в боте — бот присылает его только владельцу.
Передавать в заголовке `Authorization: Bearer <ключ>`. Ключ не сохранять в репозиторий.

| Адрес | Что делает |
| --- | --- |
| `GET /admin/messages?limit=N` | Что студенты писали боту (последние N) |
| `GET /admin/inbox` | Список присланных файлов и фото |
| `GET /admin/inbox?file=<имя>` | Скачать файл |
| `GET /admin/fetch?url=<адрес>` | Скачать страницу сайта вуза через сервер (сайты, открытые только из России). Разрешённые хосты — `FETCH_HOSTS` в `server/index.mjs` |
| `POST /admin/connected` | Благодарность подключённым: `{"ids":[tg_id], "title":"Вуз, группа", "tenant":"<id>", "group":"<группа>"}` — кнопка сразу открывает группу |
| `POST /admin/say` | Написать человеку от бота: `{"id":tg_id, "text":"…"}`. **Только по прямой команде владельца** |

Команды владельца в боте: `/stats` (охват: вузы, факультеты, динамика),
`/who`, `/say` (список групп бота; `/say <номер или id> <текст>` — написать в группу), `/offduty` / `/onduty` (снять/вернуть помощника с дежурства по входящим —
метка `#offduty` с `owner:true` в `/admin/messages`).

## Дежурство по входящим

Владелец может попросить проверять входящие раз в 30 минут: новые расписания
подключать по порядку выше и слать благодарность. Перед каждой проверкой
смотреть последнюю метку владельца в `/admin/messages`: если `#offduty` — остановиться.
