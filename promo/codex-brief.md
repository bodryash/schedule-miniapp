# :Расписание — вводная для помощника

Привет! Ты подключаешься к живому проекту. Им пользуются студенты, и любая правка, попавшая в `main`, через минуту оказывается у всех. Прочитай это целиком, прежде чем что-то менять.

## Что это

**:Расписание** — расписание пар для студентов нескольких вузов (МГИМО, МГУ, Финансовый, МАРХИ, НИЯУ МИФИ, МЭИ, ВМедА, СамГМУ и др.).

- Telegram мини-приложение, бот **@FGPshedulebot**.
- Сайт для браузера и ПК: **bodryash.ru** (то же приложение, что и app.bodryash.ru).
- Сайт-визитка: **bodryash.ru/about/**.
- Бета-версия: **beta.bodryash.ru** (ветка `beta`).
- API и бот: **api.bodryash.ru**. Это Node-сервер на VPS (SQLite, Caddy впереди).

Возможности: пары и замены, неделя и месяц, дедлайны (в том числе еженедельные), напоминания от бота, пропуски и лимиты, «Мой семестр», поиск преподавателей и аудиторий, «Подслушка» — анонимный форум студентов всех вузов, игра «Сессия 2048», темы оформления, вход на сайте через Telegram Login Widget, синхронизация настроек между телефоном и ПК.

## Как устроен репозиторий

| Папка | Что там |
|---|---|
| `docs/` | Само приложение, без сборки: `index.html`, `app.js` (основная логика), `style.css`, `forum.js/.css` (Подслушка), `game.js/.css` + `game-core.mjs` (2048), `i18n.js`, `fonts/`, `icons/` |
| `docs/about/index.html` | Сайт-визитка, отдельная самодостаточная страница |
| `docs/data/<факультет>/` | Расписания в JSON (`schedule.json`, `groups.json`) |
| `worker/src/` | Логика сервера: `index.js` (все эндпоинты, бот, напоминания), `forum.js`, `fun.js` и т. д. |
| `worker/schema.sql` | Схема базы. Только `CREATE TABLE IF NOT EXISTS`; новые колонки добавляются отдельным `ALTER TABLE` в коде, один раз |
| `server/` | Запуск на VPS (`index.mjs`, обёртка SQLite в `d1.mjs`) и тесты `*.test.mjs` |
| `deploy/` | Скрипты сервера. `update.sh` раз в минуту подтягивает `main` и перезапускает бота |
| `tools/` | Python-скрипты импорта расписаний из PDF/XLSX/сайтов вузов |

## Как работать (обязательно)

1. **Правки приложения** (`docs/`): делай в ветке `beta`, потом PR `beta → main`.
2. **Правки сервера, данных, деплоя** (`worker/`, `server/`, `deploy/`, `tools/`, `docs/data/`): отдельная ветка от свежего `origin/main`, потом PR в `main`. После слияния подтяни `main` в `beta`.
3. **Сам в `main` не сливай.** Открывай PR, сливает владелец. Всё из `main` через минуту уходит на боевой сервер.
4. Перед PR **проверь**:
   - сервер: `node server/<имя>.test.mjs`, тесты есть для `forum`, `fun`, `game`, `ref`, `remind`, `weblogin`, `prefs`, `deadline`. Новая серверная функция — новый тест.
   - сайт: `cd docs && python3 -m http.server 8126`, открой `http://localhost:8126/?app=1`. Для ПК — ширина ≥ 1100px. Проверь и телефонную ширину, 390px.
   - Telegram в тестах можно подменить заглушкой `telegram-web-app.js`, а `api.bodryash.ru` — ответом `{}`.
5. Одна задача — один PR, с понятным описанием, что и зачем.

## Правила проекта

- **Конфиденциальность.** Пропуски и личные заметки хранятся только в облаке Telegram (CloudStorage) у самого пользователя. Не отправляй их на сервер и не синхронизируй.
- **Никаких секретов и данных пользователей в репозитории**: токенов, ключей, сообщений студентов, id.
- **Все тексты для пользователей — на русском**, коротко и по-человечески. Комментарии в коде тоже на русском и объясняют «почему».
- **Бренд:** «:Расписание», значок **:P** (белый фон, чёрный символ).
- **Анимации:** только `transform` и `opacity`. Никакого `filter: blur` и анимации `clip-path`, `box-shadow`, `border-radius` на больших элементах: это даёт низкий FPS (уже проверено замерами).
- **На ПК** (`@media (min-width:1100px) and (hover:hover) and (pointer:fine)`) свой интерфейс: левое меню, правая колонка, окна по центру. Не растягивай мобильную вёрстку.
- **Не ставь `overflow` на `html`.** Это ломает «прилипающие» секции визитки. Горизонтальную прокрутку убирай в источнике.
- Вход на сайте: подпись Login Widget проверяется на сервере (`verifyWebLogin`, `web=1` в initData). В `index.html` объект `Telegram.WebApp` подменяется, потому что `initData` у настоящего скрипта только для чтения.
- Синхронизация настроек: `POST /prefs`, список ключей в `index.html`. Синхронизируются только настройки, не кэши: `schedule.look` и подобные не добавляй.

## Диагностика

- `https://bodryash.ru/?app=1&debug=1` — на странице появляется плашка с ошибками JS и данными о браузере (`&debug=0` выключает).
- `https://api.bodryash.ru/healthz` — состояние сервера, в том числе счётчики загрузки аватарок (`avatars`).
